## Judging strategy — our inference, not an official scoring addition

- Design for a stranger arriving at the public app: recognizable problem immediately, one useful action, concrete result, editable inputs, clear limits.
- Give the description and first screenshot the same before/after story, because product testing is not guaranteed.
- Treat “idea is king; presentation is queen; easy-to-understand ideas win” as the user's philosophy, not a prediction of judge behavior.
- Use equal weights in the idea tournament. The 0–10 scale in our shortlist is our planning device; the event does not publish that scale or an ELO process.
- Demonstrate Qloo removal and signal-shuffle controls. A different-looking output alone does not establish a better output.
- Build new work after the start date if later authorized; avoid depending on interpretation of the malformed existing-work provision.
- Use public hosting without login. This meets the overview's stricter public-access wording while avoiding reliance on the rules' private-credential allowance.

## Sponsor capability and access matrix

| Capability | Verified documentation | Limit that affects selection |
|---|---|---|
| Resolve names | [Search](https://github.com/qloo/docs-public/blob/main/reference/get-search.md) supports category/location filtering. | Ambiguous matches need confirmation, not invented IDs. |
| Rank a bounded set | [Insights](https://github.com/qloo/docs-public/blob/main/reference/insights-api-deep-dive.md) accepts interest entities and explicit result IDs. | A finite candidate pool is possible; rights and availability come from another source. |
| Input attribution | Same Insights reference documents `feature.explainability=true`. | Contributions may be unavailable or low-impact items omitted; no causal claim. |
| Filters | [Parameters](https://github.com/qloo/docs-public/blob/main/reference/parameters.md): geography, exclusions, category-specific price/popularity fields. | Exclusions are not negative preference learning; price tiers are not quotes. |
| Score interpretation | [Affinity guide](https://github.com/qloo/docs-public/blob/main/docs/interpreting-affinity-scores.md). | Per-query normalization; compare within-query ranks, not raw scores across users. |
| Audience contrast | [Compare endpoint](https://github.com/qloo/docs-public/blob/main/reference/analysis-compare.md). | Thin public response contract; do not invent overlap percentages. |
| Geographic taste | [Heatmaps](https://github.com/qloo/docs-public/blob/main/reference/heatmaps-use-case.md). | Affinity cells are not demand, attendance, sales or population counts. |

The current [event access document](https://github.com/qloo/qloo-hackathon-kit/blob/main/docs/API_ACCESS.md) supports `qloo explore`, `exec`, `api`, and `mcp` through the public harness using an event credential or approved gateway. They share quota. It permits necessary project caching, forbids bulk reconstruction, and leaves numerical limits/expiry to access issuance. No key was requested or tested.

The [MCP starter](https://github.com/qloo/qloo-hackathon-kit/blob/main/starter/mcp-client/README.md) documents `qloo_rank`, recommendations, audience comparison and discovery tools. Statuses include `needs_input`, `empty`, `partial`, `degraded` and `error`. Its supported deployment is a Node 22.19+ backend on a VM/container with local stdio MCP; serverless is not a supported route for that starter. This is guidance for that integration route, not an inferred prohibition on all other architectures.

The [safe-use guidance](https://github.com/qloo/qloo-hackathon-kit/blob/main/docs/SAFE_USE.md) requires aggregate-affinity interpretation and forbids sensitive/high-impact personal inference. Use explicit cultural interests without identities or account histories. The [general terms](https://www.qloo.com/legal/terms) and actual event agreement still govern output rights. Do not equate open-source application code with permission to redistribute Qloo's dataset.

API capabilities are **documented, not runtime verified**. The technical lane also found that the advertised `openapi-schema.json` appears to be a generic meta-schema, so it is not an executable endpoint contract. Do not generate implementation assumptions from it.

## Open gates

The user's subsequent originality requirement is a selection constraint, not an event rule. [The new audit](ORIGINALITY_AUDIT.md) requires a specific unmet workflow and meaningful sponsor advantage before selecting a build. In particular, the official [starter](https://github.com/qloo/qloo-hackathon-kit/blob/main/starter/mcp-client/README.md) already suggests shortlist ranking and pop-up/tour location choice; [Qloo's homepage](https://www.qloo.com/) already markets retail assortment. These broad mechanisms cannot carry an originality claim. Query-normalized ranks can support an application-layer constrained selection, but its coverage is model-output coverage, not people, sales or demand.

1. **API entitlement:** possessing documentation does not establish a usable key, available endpoints, quotas, renewal, or service through judging. Verify after implementation authorization; never expose the key in a public repository/browser.
2. **Terms:** public API output is not automatically public-domain data. Verify the account's terms for caching, screenshots, redistribution and derived outputs before implementing those behaviors.
3. **Coverage:** test the actual entity categories and geography; headline database size is not a coverage guarantee.
4. **Personal eligibility:** age, residence, employment/conflict and team details are not established here. Review official exclusions before entry.
5. **Hosting/LLM budget:** no provider, paid account, or unlimited free allocation has been assumed.
6. **Rule ambiguity:** existing-work clarification matters only if reusing a project. An organizer message would require a separate authorized action.

Research and project records are authorized. Prototyping, paid compute, recruitment, private-data collection, account creation, deployment and submission are not authorized by this research decision.
